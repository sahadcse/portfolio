# Projects Page — Research Notes (2026-10-20)

Web sources consulted for the Projects-page redesign. Patterns below were adapted to this portfolio's evidence system — no external design or text was copied.

## Sources

1. **Reddit r/webdev — "Case studies, yay or nay?"** — <https://www.reddit.com/r/webdev/comments/5xswo0/portfolio_question_case_studies_yay_or_nay> — practitioner consensus: case studies help when they explain the *why* behind decisions.
2. **dev.to — review of 40+ developer portfolios** (referenced in search results) — surface skills/projects immediately; restraint on colors/fonts; quality over quantity.
3. **Colorlib — "21 Best Developer Portfolio Examples"** — <https://www.colorlib.com/wp/category/portfolio/> — cites project pages that work as short case studies: what the tool does, links to live/GitHub, how it was built.
4. **UX Planet — navigating NDA/GDPR when showcasing work** — <https://uxplanet.org> — strategies for confidential work.
5. **Florian Boelter (LinkedIn) + Freelancing Stack Exchange — NDA framing** — an NDA doesn't forbid showing work; describe the *nature* of the work (problem, role, approach, outcome) without client specifics; the agreement's terms govern.

## Reusable patterns found

1. **Index of concise summaries** — each card answers: what it is, the problem/purpose, the stack, and a link deeper (live or case study). Depth lives on the case-study page, not the index.
2. **Problem → process → solution → outcome** as the case-study spine (matches this portfolio's §9.1 template already: problem → built → how → outcomes).
3. **Quality over quantity** — a curated set beats an exhaustive dump; volume can be stated, not padded ("25+ delivered, 10+ shown" is exactly this pattern).
4. **Anonymized/nature-of-work descriptions for confidential items** — describing the *kind* of system and the role is legitimate; specifics are not. This directly supports the private/internal-work explanation on the page.
5. **Real categories only** — filters help discovery when the taxonomy matches the actual work; invented categories add noise.

## Applied here

- Informative opening + compact 25+/10+/private summary strip (pattern 3).
- Kept the existing sector filter (pattern 5 — the sectors mirror the verified §9.3 metric) and evidence-tier chips (pattern 1 — cards state what kind of work each item is).
- Added a short private/internal-work explainer (pattern 4) instead of padding the grid with undisplayable items.
- Kept per-card one-line outcomes and deep links to full case studies (pattern 2's spine already implemented in the §9.1 template).
